# Minecraft Side Project

A MonoGame client and a console server that share one block library.

## Projects

| Project | Type | Purpose |
| --- | --- | --- |
| `src/Minecraft.Client` | MonoGame desktop app | Renders the 3D block world |
| `src/Minecraft.Server` | Console app | Owns the world and runs server commands |
| `src/Minecraft.Shared` | Class library | Blocks, world data, and other code used by both sides |

The client and server both reference `Minecraft.Shared`, so block definitions
and world logic only exist in one place.

## Running

From Git Bash, run the client and server together with one command:

```bash
./run.sh
```

That builds the solution once, opens the server in its own console window, and
starts the client. Type commands in the server window — for example:

```text
set 16 15 16 stone
```

The change is sent to every connected client and appears immediately.

Other modes:

```bash
./run.sh client    # build and run only the game client
./run.sh server    # build and run only the console server
./run.sh debug     # build, then open the workspace in VS Code if the code command is available
```

Use `bash run.sh` if the executable bit was lost (for example after copying the
folder).

### Debugging

VS Code debugging is set up for all three projects. Open **Run and Debug** and
choose one of:

| Configuration | What it does |
| --- | --- |
| `Client (Debug)` | Game client with the debugger attached |
| `Server (Debug)` | Console server in an integrated terminal, so commands still work |
| `Client + Server (Debug)` | Both at once; stopping one stops both |

Set breakpoints directly in `src/Minecraft.Shared` — the shared library is
compiled into both executables, so its code is debuggable from either session.

The default build task (`Ctrl+Shift+B`) builds the client, server, and shared
library together.

The same processes can be started manually:

```bash
dotnet build Minecraft.sln
dotnet run --project src/Minecraft.Client
dotnet run --project src/Minecraft.Server
```

## Multiplayer

Networking uses [Lidgren.Network](https://github.com/AscensionGameDev/Lidgren.Network)
(UDP) via the `AscensionGameDev.Lidgren.Network` NuGet package. The server owns
the world and listens on UDP port `25565` with the app identifier
`MinecraftSideProject`. Players on your network can join by pointing the client
at the server's IP address.

When a client connects, the server sends a full world snapshot, then broadcasts
a block update for every `set` command (and for block edits reported by clients).
The client polls Lidgren each frame on the game thread and rebuilds its mesh, so
changes appear live. If the connection drops, the client keeps retrying in the
background.

To play with someone else, change the host in
`src/Minecraft.Client/Game1.cs` (the `_connection.Start(...)` call) to the
server machine's IP address and allow UDP `25565` through the firewall.

If the server is not running, the client still starts with a locally generated
world and shows `server not running` in the window title.

Server commands:

```text
blocks                        List every registered block
stats                         Count blocks in the world
get <x> <y> <z>               Read a block
set <x> <y> <z> <block>       Place a block (updates all clients live)
help                          Show the command list
quit                          Stop the server
```

The client builds and renders the shared 3D world as colored cubes. The world
currently contains a flat grass landscape with a few trees, generated by
`FlatWorldGenerator` in the shared library.

Controls:

```text
W / A / S / D        Move
Mouse                Look around
Space / Left Shift   Fly up / down
Escape               Quit
```

Because the mouse is captured for looking, close the window or press Escape to
exit.

## Adding a block

Add a member to `BlockId` and an entry to `BlockRegistry` in
`src/Minecraft.Shared/Blocks`:

```csharp
// BlockId.cs
Snow = 8,

// BlockRegistry.cs
new(BlockId.Snow, "Snow", 0xF2F7FA, IsSolid: true, IsTransparent: false),
```

That is all it takes. The client renderer and the server's `blocks` command both
read from `BlockRegistry`, so the new block automatically appears in both.
